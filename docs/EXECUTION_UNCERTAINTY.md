# Stage 290: execution answers, U-Space, and lens words

This is a standalone behavioural evaluation. It performs **no fine-tuning,
probe training, steering, or layer selection**. The model completes an assertion
for an existing benchmark function and input. Python verifies the published
answer during preparation; generated answers are parsed as literals, never executed.

The default model is `deepseek-coder-1.3b`, with the existing stage-201 J-lens.
Default readout: **zero-based block 6, raw post-block residual at the last prompt
token, immediately before answer generation**. This is a configurable initial
choice, not a validated best layer for uncertainty.

## Cluster commands

From the repository root, using the existing cluster environment and fitted
`results/workspace_lens/deepseek-coder-1.3b/j-lens/lens.pt`:

```bash
# CPU, with network access: download and verify both published datasets.
bash jobs/execution_uncertainty.sh prepare

# Inside a GPU allocation: one model/dataset run at a time, resumable.
bash jobs/execution_uncertainty.sh evaluate
```

The launcher defaults to `.venv/bin/python`. Override it with `PYTHON=python`.
It does not submit a scheduler job or request a GPU. The script loads the vendored
`jlens` implementation automatically; no U-Space package installation is needed.
Standard repository dependencies (including datasets, PyYAML, sklearn) are used.

Change the location or model using environment variables:

```bash
LAYER=5 LOCATION=code_end DATASETS=cruxeval bash jobs/execution_uncertainty.sh evaluate
```

For a small first GPU run, use a separate output directory:

```bash
.venv/bin/python scripts/290_execution_uncertainty.py evaluate \
  --prepared results/execution_uncertainty/prepared/cruxeval \
  --output results/execution_uncertainty/smoke \
  --model deepseek-coder-1.3b --layer 6 --location prompt_end \
  --limit 10 --top-k 20 --resume
```

Preparation can use an offline JSONL export instead of the Hub:

```bash
.venv/bin/python scripts/290_execution_uncertainty.py prepare \
  --dataset cruxeval --input-jsonl /path/to/cruxeval.jsonl \
  --output results/execution_uncertainty/prepared/cruxeval
```

Online preparation resolves the dataset revision to a commit and records it.
Offline exports retain their SHA-256 and are labelled as offline exports; callers
are responsible for exporting the intended published split. GPU evaluation needs
cached model/tokenizer weights or Hub access. `HF_HUB_OFFLINE=1` can force cache use.
No benchmark code or inputs are generated by this stage.

## Dataset and answer rules

- **MBPP:** original `full` configuration, published **test** split, reference
  code and original test calls. Only assertions of the form `call(...) == literal`
  are eligible. Test setup code is included in execution and in the model prompt.
- **CRUXEval-O:** published test functions, inputs, and outputs; no binding-task
  filters, so this is not limited to the 66 candidates from stage 280.
- Supported output values: integers, booleans, strings, `None`, and recursively
  nested lists/tuples of those types. Floats, sets, dictionaries, arbitrary
  expressions, and unsupported assertions are explicitly excluded.
- Each reference call runs twice in fresh processes. Both results must agree
  with the published expected value, recursively checking types. Two successful
  runs are a consistency check, not a proof of determinism for all environments.
- Reference execution uses a temporary working directory, isolated Python,
  timeouts, and resource limits (address-space limits on Linux only). This is
  process isolation, **not a security sandbox**; use trusted published exports.
- Model responses use a strict single-line Python-literal format. `True` does
  not count as `1`, and a list does not count as a tuple. Invalid responses count
  as incorrect and are also reported separately.
- Greedy generation stops at the first newline, EOS, or the token budget. All
  stopping reasons are retained. Prompts exceeding the context budget are
  excluded with a reason, never silently truncated.

The zero-shot prompt contains the reference code, test setup if present, and
`assert <published call> ==`. It does not include the expected answer or problem
description. This is an execution-prediction adaptation of MBPP, not its official
code-generation metric. Public benchmark contamination remains possible.

## Read locations

| `--location` | Residual sampled after processing |
|---|---|
| `prompt_end` (default) | Last prompt token, immediately before the answer |
| `code_end` | Token containing the final non-whitespace code character |
| `answer_end` | Last token contributing non-whitespace content to the generated answer |
| `token_index --token-index N` | Absolute zero-based token N, including the explicitly prepended BOS |

Block numbers are zero-based **transformer block indices**, not Hugging Face
hidden-state tuple indices. The raw block output is captured with a hook. Every
record includes its actual read token ID, decoded token, index, prompt character
span where available, and whether it follows the beginning of the generated answer.
Tokens can straddle the code/newline or answer/newline boundary; they are reported
literally. An empty answer has no `answer_end` readout; its correctness still counts.

Generation uses the KV cache. A second forward pass over the identical token IDs
captures the requested position. The ground-truth answer is never teacher-forced.
Reading a prompt position remains causal even when the replay includes later tokens.

## Score definitions and top words

The four anchor/pole lists are pinned, unmodified copies from
[U-Space](https://github.com/s2labres/U-Space), commit
`cce4d2633ed763ba9b33efb11c7099a361209129`, with the BSD-3-Clause license in
`third_party/u-space/`. Actual single-token anchor coverage is saved in `basis.json`.

For each anchor/pole word, use the first single-token spelling from a leading-space
variant and the bare word. Pull its unembedding row back with the final RMSNorm
gain and the existing Jacobian, normalize, contrast anchor/pole centroids, then
apply symmetric Lowdin orthonormalization. Empty categories or rank-deficient
contrasts fail rather than silently producing an invalid basis.

For column-orthonormal basis `U` and residual `h`:

```text
z       = U.T @ unit(h)
zhat    = z / (norm(z) + 1e-30)
a_cone  = norm(softplus(sqrt(4) * zhat))
ulens_score = a_cone * mean_answer_entropy
```

`a_cone` is the published U-Space cone score. `category_cosines` stores `z`;
`category_normalized` stores `zhat`. `uspace_projection_norm` helps identify
states with tiny projections whose normalized category profile could be unstable.
The cone formula is not simply the size of the projection.

**The entropy window is an adaptation.** The upstream score combines an
end-of-thinking state with mean thinking-token entropy. This base code model has
no end-of-thinking delimiter. We instead combine the chosen location with mean
predictive entropy over tokens generating the answer. EOS and newline-only stop
tokens are excluded; a token containing both answer content and newline is included.
Logits at position t predict token t+1. Empty answers have null composite scores.
The score is not a calibrated probability of error, and prompt-end composite
scores still use entropy observed during subsequent answer generation.

Two different full-vocabulary top-k lists are saved at the same location:

1. **`top_jlens_tokens`:** final norm and LM head applied to `J @ h`. This is
   the ordinary J-lens readout of the entire residual.
2. **`top_uspace_tokens`:** final norm and LM head applied to
   `J @ (U @ U.T @ h)`. This is an **exploratory vocabulary decoding of the
   signed U-Space projection**, not a standard word-output component of the
   published U-Lens. Negative category components are retained.

Both are literal vocabulary-token rankings: whitespace, punctuation, and subword
fragments are retained, with token IDs and raw scores. They are not reconstructed
whole words, probabilities, or validated explanations of why execution failed.
The category readouts are the published-style uncertainty interpretation.

Currently restricted to models with bias-free RMSNorm and a matching, provenance-
identified stage-201 J-lens. There is no logit-lens fallback for a missing layer.
The default DeepSeek-Coder models meet the architectural requirement; LayerNorm
models such as StarCoder2 are rejected by this implementation.

## Outputs and resumption

Under `results/execution_uncertainty/<model>/block<layer>-<location>/<dataset>/`:

| File | Contents |
|---|---|
| `predictions.jsonl` | Code, call, expected/predicted answers, correctness, entropy, category scores, read token and both top-k lists |
| `metrics.json` | Call/macro accuracy, invalid answers, error-detection AUROC and selective error rates |
| `report.md` | Main metrics, definitions, and first ten evaluated examples with literal top tokens |
| `config.json` | Model commit when available, tokenizer/artifact/source hashes, layer/location and generation settings |
| `basis.json` | U-Space basis, category order, retained words/token IDs, conditioning diagnostics |
| `rows/*.json` | Atomic per-example checkpoints for resumption |
| `gates.json` | Completion status and output hashes |

Preparation separately saves eligible `cases.jsonl`, `exclusions.jsonl`, and provenance.
No inferential significance is claimed by this basic report. AUROC is a descriptive
call-level measure, with null for single-class outcomes. Program-macro accuracy
groups exact-source duplicates together. Selective error uses the lowest-uncertainty
80% target with all cutoff ties retained, reporting actual coverage. Null scores are
excluded only from the affected uncertainty metric, with denominators recorded.

`--resume` requires identical settings/artifact hashes and reuses completed row
files. New layers, locations, token budgets, or subsets require new output
directories. Failed/interrupted runs never acquire a passing completion gate.

## Local verification

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest tests/test_execution_uncertainty.py -q
```

Tests cover execution verification/exclusions, non-executing type-strict answer
grading, published-formula equivalence, causal token positions, predictive-entropy
alignment, and an offline tiny-model end-to-end run with resumption. They do not
substitute for the first cluster smoke run on DeepSeek-Coder and its fitted lens.
